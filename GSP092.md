# GSP092 – Cloud Monitoring: Cloud Run Functions

## Known lab traps (read first)

1. Deploy with `gcloud functions deploy --gen2`, not `gcloud run deploy`. The checker looks for the function through the Cloud Functions API, and a service deployed with `gcloud run deploy --function` fails the check even though all its settings match. A gen2 function still appears in Cloud Run as helloworld.
2. The region is blank in the lab text ("Region: ____") and changes per lab instance. Use the region shown in your lab instructions or the Lab setup panel.
3. The lab's `CLOUD_RUN_URL=...` command has an empty `--region=`, so it fails as written. Fixed below.
4. vegeta runs for 5 minutes and ties up the terminal. Here it runs in the background so you can keep working.
5. The logs-based metric shows as "Not Active" in Metrics Explorer for the first few minutes. Uncheck Active to find it. This doesn't affect the checkpoint.

## Setup (edit to match your lab)

```bash
echo us-east1 > ~/region
gcloud config get-value project > ~/project

```

## Task 1 – Create the Cloud Run function

Block 1 – the function code and deploy (Node.js 22, public, second generation, max 5 instances):

```bash
mkdir -p ~/helloworld && cd ~/helloworld
cat > index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');

functions.http('helloHttp', (req, res) => {
  res.send('Hello World!');
});
EOF
cat > package.json <<'EOF'
{
  "dependencies": {
    "@google-cloud/functions-framework": "^3.0.0"
  }
}
EOF
gcloud functions deploy helloworld --gen2 --runtime=nodejs22 --region=`cat ~/region` \
  --source=. --entry-point=helloHttp --trigger-http --allow-unauthenticated --max-instances=5 --quiet
gcloud functions list --format="table(name,state,environment)"
```

The deploy takes 2–4 minutes. When it's done, the list should show helloworld, ACTIVE, GEN_2.

Block 2 – install vegeta: run the lab's two vegeta commands (curl, then tar) from its copy buttons.

Block 3 – save the URL, test it, and start traffic in the background:

```bash
cd ~
gcloud run services describe helloworld --region=`cat ~/region` --format='value(status.url)' > ~/url
cat ~/url
curl -s `cat ~/url`; echo
echo "GET `cat ~/url`" | nohup ./vegeta attack -duration=300s -rate=200 > results.bin 2>/dev/null &
echo vegeta-started
```

You should see "Hello World!" before vegeta starts.

## Task 2 – Create a logs-based metric

```bash
cd ~
cat > metric.yaml <<'EOF'
filter: resource.type="cloud_run_revision" AND resource.labels.service_name="helloworld"
valueExtractor: EXTRACT(httpRequest.latency)
metricDescriptor:
  metricKind: DELTA
  valueType: DISTRIBUTION
bucketOptions:
  exponentialBuckets:
    numFiniteBuckets: 64
    growthFactor: 2
    scale: 0.01
EOF
gcloud logging metrics create CloudRunFunctionLatency-Logs --config-from-file=metric.yaml
gcloud logging metrics list --format="table(name,metricDescriptor.valueType)"
```

This is the same Distribution metric the lab builds in Logs Explorer, on the httpRequest.latency field.
